# AON · Asset and Operational Network

โปรแกรมวาดผังเครือข่ายและทะเบียนอุปกรณ์ (เดิมชื่อ NetPlan)

โปรแกรมบนเว็บสำหรับวาด network diagram มีอุปกรณ์ให้เลือก 18 ชนิด เช่น Router, Firewall, Core Switch, Switch, Media Converter, Wireless Controller, Access Point, Server, Database, NAS, PC, Laptop, Printer, IP Phone, กล้อง CCTV, UPS และใส่รายละเอียดของแต่ละอุปกรณ์ได้ (IP, Subnet, Gateway, VLAN, MAC, Service port, Time sync (NTP server), ยี่ห้อ, รุ่น, Serial, Hypervisor / Virtualization Platform (Nutanix / VMware / Proxmox), OS, สถานที่ติดตั้ง (เลือกจากรายการหรือพิมพ์เอง), Antivirus / EDR (หมวด Protection), Database, ภาษาที่ใช้พัฒนา และเวอร์ชัน, Nginx version (หมวดซอฟต์แวร์), สถานะ, หมายเหตุ และฟิลด์ที่เพิ่มเองได้) ผังจะถูกบันทึกเป็นไฟล์ JSON บนเซิร์ฟเวอร์เมื่อกดปุ่ม “บันทึก” (หรือ Ctrl+S) หรือติ๊ก “อัตโนมัติ” ให้บันทึกเองทุกครั้งที่แก้ไข

## วิธีติดตั้งด้วย Docker

ต้องมี Docker และ Docker Compose (Docker Desktop มีให้ครบแล้ว)

```bash
cd netplan
docker compose up -d --build
```

จากนั้นเปิดเบราว์เซอร์ไปที่ **http://localhost:8080** (หรือ `http://<IP ของเครื่อง>:8080` จากเครื่องอื่นในวง LAN)

คำสั่งที่ใช้บ่อย

| ต้องการ | คำสั่ง |
|---|---|
| ดู log | `docker compose logs -f` |
| หยุดโปรแกรม | `docker compose down` |
| อัปเดตหลังแก้ไฟล์ | `docker compose up -d --build` |
| เปลี่ยนพอร์ต | แก้ `"8080:8080"` ใน `docker-compose.yml` เป็น เช่น `"9000:8080"` |

ข้อมูลทั้งหมดเก็บที่โฟลเดอร์ `./data` ในโปรเจกต์ (mount เป็น `/data` ในคอนเทนเนอร์) เปิดดูหรือ copy ได้จากข้างนอกโดยไม่ต้องเข้าคอนเทนเนอร์ และไม่หายเมื่อสั่ง `down` หรือ build ใหม่
- `data/<id>.json` ไฟล์ละผัง
- `data/auth/users.json`, `sessions.json`, `settings.json` บัญชีผู้ใช้ session และค่าตั้งค่าอีเมล
- `data/auth/audit.db` บันทึกการใช้งาน (SQLite; อาจมีไฟล์ `audit.db-wal` / `audit.db-shm` คู่กันตอนระบบรันอยู่)

ไฟล์บัญชีใน `data/auth` เซิร์ฟเวอร์อ่านเก็บไว้ในหน่วยความจำและเขียนทับเมื่อมีการเปลี่ยน ถ้าจะแก้ด้วยมือให้ `docker compose stop netplan` ก่อน แก้เสร็จแล้วค่อย `docker compose start netplan` โฟลเดอร์ `data/` และ `backups/` ไม่ถูกส่งขึ้น git

ตอนอัปเกรดครั้งแรกจากเวอร์ชันที่ใช้ `audit.log` ระบบจะคัดลอกรายการเดิมเข้า `audit.db` ครั้งเดียว แล้วเปลี่ยนชื่อไฟล์เก่าเป็น `audit.log.imported` (เก็บไว้ ไม่ลบ)

สำรองข้อมูล: `scripts/backup-data.sh` บีบอัด `data/` ไว้ที่ `backups/netplan-data-<วันเวลา>.tgz` และลบไฟล์ที่เก่ากว่า 30 วัน (ตั้งจำนวนวันได้ด้วย `KEEP_DAYS`) ตั้งให้รันทุกวันด้วย cron เช่น

```bash
30 2 * * * /home/api/networkdiagram/scripts/backup-data.sh >> /home/api/networkdiagram/backups/backup.log 2>&1
```

กู้คืน: `docker compose stop netplan` แล้วแตกไฟล์สำรองทับ (`tar -xzf backups/netplan-data-<วันเวลา>.tgz`) จากนั้น `docker compose start netplan`

## ผู้ใช้และสิทธิ์การใช้งาน

เมื่อเปิดผ่านเซิร์ฟเวอร์ ทุกคนต้องเข้าสู่ระบบก่อนใช้งาน

- **บัญชีแรก** ที่สมัครจะเป็นผู้ดูแลระบบ (admin) และใช้งานได้ทันทีโดยไม่ต้องยืนยันอีเมล ควรสมัครบัญชีนี้ทันทีหลังติดตั้ง
- **บัญชีถัดไป** ต้องกดลิงก์ยืนยันที่ส่งไปทางอีเมลก่อนจึงเข้าใช้ได้ และเริ่มต้นเป็นสถานะ “รออนุมัติ” (เข้าสู่ระบบได้แต่ยังไม่เห็นผัง) จนกว่าผู้ดูแลระบบจะกำหนดสิทธิ์ให้
- **สิทธิ์** มี 3 ระดับ ผู้ดูแลระบบจัดการได้ที่เมนูชื่อผู้ใช้มุมขวาบน → “จัดการผู้ใช้และอีเมล”

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| ผู้ดูแลระบบ (admin) | ทุกอย่าง เพิ่ม ลบ แก้ไขผัง จัดการผู้ใช้ ตั้งค่าการส่งอีเมล |
| ผู้แก้ไข (editor) | เพิ่ม ลบ แก้ไขผัง |
| ดูอย่างเดียว (viewer) | เปิดดู ค้นหา และส่งออก PNG/SVG/CSV ได้ แต่แก้ไขไม่ได้ |
| รออนุมัติ (pending) | เข้าสู่ระบบได้ แต่ยังไม่เห็นผังใด ๆ |

**ตั้งค่าการส่งอีเมล** ที่หน้า “จัดการผู้ใช้และอีเมล” ใส่เซิร์ฟเวอร์ SMTP พอร์ต ชื่อผู้ใช้ รหัสผ่าน และผู้ส่ง แล้วกด “ส่งอีเมลทดสอบถึงตัวเอง” ตัวอย่างเช่น Gmail ใช้ `smtp.gmail.com` พอร์ต `587` กับ App password ของบัญชี Google ช่อง “ที่อยู่เว็บที่ใส่ในลิงก์อีเมล” ต้องเป็นที่อยู่ที่ผู้ใช้เปิดได้ เช่น `http://192.168.1.10:8088`

ถ้ายังไม่ได้ตั้งค่าอีเมล ลิงก์ยืนยันและลิงก์ตั้งรหัสผ่านใหม่จะแสดงใน log (`docker compose logs`) หรือผู้ดูแลระบบกด “ยืนยันให้” ที่รายชื่อผู้ใช้ได้เลย

**การยืนยันตัวตน 2 ขั้น (MFA)** ใช้รหัส 6 หลักจากแอป Google Authenticator / Microsoft Authenticator (TOTP) ค่าเริ่มต้นบังคับเฉพาะผู้ดูแลระบบ: admin ที่ยังไม่ได้ตั้งค่าจะต้องสแกน QR code และกรอกรหัสก่อนใช้งานอื่นได้ หลังตั้งค่าจะได้รหัสสำรอง 10 รหัส (ใช้ได้รหัสละครั้ง) ไว้ใช้ตอนทำมือถือหาย

- เปลี่ยนว่าจะบังคับสิทธิ์ไหนบ้างได้ที่ “จัดการผู้ใช้และอีเมล” → การยืนยันตัวตน 2 ขั้น (หรือตัวแปร `MFA_REQUIRED=admin,editor` ใช้เมื่อยังไม่เคยตั้งในหน้าเว็บ, `MFA_REQUIRED=` ว่าง = ไม่บังคับ)
- ผู้ใช้ทุกคนเปิดใช้เองได้ที่เมนูชื่อผู้ใช้ → “การยืนยันตัวตน 2 ขั้น (MFA)” และสร้างรหัสสำรองชุดใหม่ได้ที่เดียวกัน
- ผู้ใช้ทำมือถือหาย: ผู้ดูแลระบบอีกคนกด “รีเซ็ต MFA” ที่รายชื่อผู้ใช้ ผู้ใช้จะต้องตั้งค่าใหม่ตอนเข้าสู่ระบบครั้งถัดไป
- ผู้ดูแลระบบคนเดียวทำมือถือและรหัสสำรองหาย: รันบนเครื่อง server

  ```bash
  docker compose exec netplan node server.js reset-mfa admin@example.com
  docker compose restart netplan
  ```

**บันทึกการใช้งาน (Activity log)** ผู้ดูแลระบบเปิดดูได้ที่เมนูชื่อผู้ใช้ → “บันทึกการใช้งาน” ระบบบันทึกการเข้าสู่ระบบ (ทั้งสำเร็จและไม่สำเร็จ พร้อม IP) การสมัคร การเปลี่ยนสิทธิ์ การลบผู้ใช้ การสร้าง/ลบผัง และการแก้ไขผังว่าเปลี่ยนอะไรบ้าง เช่น เพิ่ม/ลบอุปกรณ์ แก้ IP จากค่าเดิมเป็นค่าใหม่ การแก้ไขของคนเดียวกันในช่วงเวลาใกล้กันจะรวมเป็นรายการเดียว กรองตามผู้ใช้ ผัง ประเภท วันที่ หรือคำค้นได้ และส่งออกเป็น CSV ได้ เก็บที่ `data/auth/audit.db` (SQLite)

ข้อมูลผู้ใช้เก็บที่ `data/auth` โฟลเดอร์เดียวกับผัง (รหัสผ่านเก็บแบบ scrypt hash) ถ้าต้องการปิดระบบล็อกอินแบบเดิม ให้ตั้งตัวแปร `AUTH=off`

## รันโดยไม่ใช้ Docker

ต้องมี Node.js 22.5 ขึ้นไป (แนะนำ 24 LTS ซึ่งยังได้รับแพตช์ความปลอดภัย) เพราะบันทึกการใช้งานใช้โมดูล `node:sqlite` ในตัว ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm start
# หรือ
node server.js        # ข้อมูลเก็บที่โฟลเดอร์ ./data
```

## ทดสอบอัตโนมัติ

ชุดทดสอบใน `test/` เปิดเซิร์ฟเวอร์จริงบนพอร์ตว่าง พร้อมโฟลเดอร์ข้อมูลชั่วคราว แล้วตรวจ login สิทธิ์ admin/editor/viewer/pending การกันบันทึกทับด้วยเลขรุ่นผัง (409/410) live update และบันทึกการใช้งาน ต้องใช้ Node.js เวอร์ชันเดียวกับที่รันเซิร์ฟเวอร์ (มี `node:sqlite`)

```bash
npm test
# หรือถ้าเครื่องนี้ยังเป็น Node เก่า ให้รันด้วย image ที่ build ไว้แล้ว
docker run --rm -v "$PWD":/work -w /work --entrypoint node netplan:latest --test --test-concurrency=1 test/api.test.js test/audit.test.js
```

## วิธีใช้งาน

- **เพิ่มอุปกรณ์** คลิกหรือลากจากแถบด้านซ้าย
- **ใส่รายละเอียด** คลิกอุปกรณ์แล้วกรอกที่แผงด้านขวา แต่ละชนิดมีช่องเฉพาะ เช่น AP มี SSID/Channel, Firewall มี HA/Security zones และกด “+ เพิ่มฟิลด์” เพื่อเพิ่มช่องเองได้
- **เชื่อมสาย** กดปุ่ม “เชื่อมสาย” (คีย์ลัด C) เลือกชนิดสาย (UTP, Fiber, WAN, VPN, Wireless, Stack/HA) แล้วลากจากอุปกรณ์หรือโซนหนึ่งไปอีกอันหนึ่ง (เชื่อมอุปกรณ์↔อุปกรณ์, อุปกรณ์↔โซน หรือโซน↔โซน ได้) คลิกที่สายเพื่อใส่พอร์ตทั้งสองฝั่งและความเร็ว เลือกรูปแบบเส้นได้ทั้ง “เส้นตรง” และ “เส้นหักมุม” (หักฉากแบบมุมโค้ง หาทางอ้อมโซนและอุปกรณ์ที่ขวางให้อัตโนมัติ และแยกเส้นที่วิ่งซ้อนกันออกจากกัน) จากเมนูบนแถบเครื่องมือ หรือเปลี่ยนทีละเส้นที่แผงด้านขวา เส้นหักมุมลากปรับแนวเองได้ โดยคลิกเลือกสายแล้วลากช่วงใดของเส้น (หรือจุดจับสีเหลือง) ไปตำแหน่งที่ต้องการ กด “จัดแนวเส้นอัตโนมัติ” เพื่อกลับไปให้ระบบหาเส้นทางให้ เส้นตัดกันได้ โดยจุดที่สายตัดผ่านกันจะมีโค้งข้ามเล็ก ๆ ให้เห็นว่าไม่ได้เชื่อมถึงกัน ชื่อพอร์ตและป้ายบนสายอยู่ในกรอบของตัวเองและหาที่ว่างให้อัตโนมัติไม่ให้ทับกันหรือทับชื่ออุปกรณ์ ถ้ายังไม่ถูกใจลากข้อความไปวางเองได้ (ถ้าลากไปไกลจะมีเส้นประชี้กลับไปที่สาย) กด “จัดข้อความอัตโนมัติ” ที่แผงด้านขวาเพื่อกลับไปให้ระบบจัดให้
- **โซน / VLAN** กด “วาดโซน” (Z) แล้วลากเป็นกรอบ ลากกรอบเพื่อย้ายทั้งโซนพร้อมอุปกรณ์ข้างใน
- **เปลี่ยนสี** คลิกอุปกรณ์หรือโซน แล้วเลือกสีที่แผงด้านขวา เลือกได้ทุกเฉดจากตัวเลือกสี พิมพ์รหัสสี (เช่น `#1b7a8c`) หรือกดสีสำเร็จรูปก็ได้ อุปกรณ์กด “ใช้สีตามชนิดอุปกรณ์” เพื่อกลับเป็นสีเดิม
- **เลือกหลายชิ้น** กด Shift ค้างแล้วคลิกทีละชิ้น, กด Shift ค้างแล้วลากกรอบบนพื้นที่ว่าง หรือกด Ctrl+A เพื่อเลือกทั้งหมด (บนแท็บเล็ตใช้ปุ่ม “เลือกหลายชิ้น” มุมขวาล่าง) จากนั้นลากชิ้นใดก็ได้เพื่อย้ายทั้งกลุ่ม เปลี่ยนสีหรือสถานะพร้อมกันที่แผงด้านขวา หรือกด Delete เพื่อลบทั้งหมด
- **ค้นหา** พิมพ์ในช่องค้นหาบนพื้นที่วาด (หรือกด Ctrl+F) ค้นได้ทั้งภาษาไทยและอังกฤษ จากชื่อ, IP, VLAN, MAC, ยี่ห้อ/รุ่น, Serial, สถานที่ติดตั้ง, หมายเหตุ และฟิลด์ที่เพิ่มเอง พิมพ์หลายคำเพื่อกรองให้แคบลง (เช่น `vlan 40 ap`) กด Enter หรือคลิกผลลัพธ์เพื่อเลื่อนไปที่อุปกรณ์นั้น
- **ภาษา** กดปุ่ม ไทย / EN มุมขวาบนเพื่อสลับภาษาเมนูทั้งหมด ระบบจะจำภาษาที่เลือกไว้ในเบราว์เซอร์
- **ส่งออก** เป็นรูป PNG / SVG, รายการอุปกรณ์ CSV (เปิดใน Excel ได้ภาษาไทย) หรือไฟล์ผัง JSON
- **ผังทั้งหมด** ดู เปิด สร้าง หรือลบผังที่เก็บบนเซิร์ฟเวอร์
- **บันทึก** เมื่อแก้ไขผังแล้ว ปุ่ม “บันทึก” ข้างปุ่มย้อน/ทำซ้ำจะกดได้ และมุมขวาบนขึ้นว่า “ยังไม่บันทึก” กดบันทึก (หรือ Ctrl+S) เพื่อเก็บขึ้นเซิร์ฟเวอร์ ถ้าติ๊ก “อัตโนมัติ” ระบบจะบันทึกให้เองทุกครั้งที่แก้ (จำค่าไว้ในเบราว์เซอร์นั้น) ระหว่างยังไม่บันทึก งานที่แก้จะเก็บไว้ในเบราว์เซอร์ก่อน ปิดหน้าแล้วเปิดใหม่ก็ยังอยู่ และระบบจะถามก่อนปิดหน้า เปิดผังอื่น หรือออกจากระบบ
- **กรองตามสถานที่ติดตั้ง** คลิกพื้นที่ว่างให้แผงด้านขวาแสดงข้อมูลผัง แล้วเลือกจาก “กรองตามสถานที่ติดตั้ง” ซึ่งดึงรายการจากช่องสถานที่ติดตั้งของอุปกรณ์ในผัง พร้อมจำนวนเครื่อง เลือกแล้วเครื่องที่ตรงกันจะเด่นขึ้นในผังและแสดงรายการให้คลิกไปที่เครื่องได้ (ผู้ใช้แบบดูอย่างเดียวก็ใช้ได้)- **ทำงานพร้อมกันหลายคน** เปิดผังเดียวกันได้หลายคนพร้อมกัน มุมขวาบนแสดงวงกลมชื่อย่อของคนที่เปิดผังนี้อยู่ และชิ้นที่แต่ละคนเลือกอยู่จะมีกรอบสีของคนนั้นพร้อมชื่อ เมื่อมีคนบันทึก การแก้ไขของเขาจะขึ้นบนจอของทุกคนทันที (ติ๊ก “อัตโนมัติ” ไว้ จะเห็นการแก้ไขของกันและกันแทบจะสด ๆ) ถ้าระหว่างนั้นคุณแก้อยู่ ระบบจะรวมให้เอง งานของคุณที่ยังไม่บันทึกไม่หาย และไม่มีใครเขียนทับงานของอีกคน ถ้าสองคนแก้ช่องเดียวกันของชิ้นเดียวกันเป็นค่าต่างกัน ตอนบันทึกระบบจะให้เลือกว่าจะเก็บค่าของใครทีละช่อง ส่วนการย้ายตำแหน่งที่ชนกัน ระบบใช้ตำแหน่งของคนที่บันทึกทีหลัง ปุ่มย้อน (Ctrl+Z) ย้อนเฉพาะงานของตัวเอง
- จุดสีที่มุมขวาบนของอุปกรณ์บอกสถานะ: เขียว = ใช้งานอยู่, น้ำเงิน = วางแผน / ยังไม่ติดตั้ง, ส้ม = ซ่อมบำรุง, ม่วง = รอปิดการใช้งาน, แดง = ไม่ได้ใช้งาน (ชี้เมาส์ที่จุดเพื่อดูชื่อสถานะ)
- อุปกรณ์ที่กรอก “บทบาท / บริการ” (ในหมวดรายละเอียดเซิร์ฟเวอร์) จะแสดงข้อความนั้นเป็นบรรทัดที่ 3 ใต้ชื่อและ IP
- คีย์ลัด: Delete ลบ · Ctrl+S บันทึก · Ctrl+Z ย้อน · Ctrl+Y ทำซ้ำ · Ctrl+D ทำสำเนา · Ctrl+X ตัด · Ctrl+C คัดลอก · Ctrl+V วาง (ใช้กับชิ้นที่เลือกไว้ทั้งกลุ่ม สายที่เชื่อมกันภายในกลุ่มติดไปด้วย วางตรงตำแหน่งเมาส์ และวางข้ามผังได้) · ลูกศรเลื่อนอุปกรณ์ · F หรือปุ่ม “เต็มจอ” ดูพื้นที่วาดแบบเต็มจอ · ล้อเมาส์เลื่อนขึ้นลง · Shift+ล้อเมาส์เลื่อนซ้ายขวา · Ctrl+ล้อเมาส์ซูม

## ฟอนต์ภาษาไทย

ฟอนต์ IBM Plex Sans Thai และ IBM Plex Mono อยู่ในโฟลเดอร์ `public/fonts` (สัญญาอนุญาต SIL Open Font License ดู `public/fonts/OFL-LICENSE.txt`) จึงแสดงภาษาไทยได้เหมือนกันทุกเครื่อง แม้ใช้งานในวง LAN ที่ไม่มีอินเทอร์เน็ต และไฟล์ PNG/SVG ที่ส่งออกก็ฝังฟอนต์ไว้ในตัว

## API (สำหรับเชื่อมกับระบบอื่น)

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/diagrams` | รายการผังทั้งหมด |
| POST | `/api/diagrams` | สร้างผังใหม่ คืนค่า `{ id }` |
| GET | `/api/diagrams/:id` | อ่านผัง (มี `rev` เลขรุ่นของผัง) |
| PUT | `/api/diagrams/:id` | บันทึกผัง คืนค่า `{ id, rev, updatedAt }` |
| DELETE | `/api/diagrams/:id` | ลบผัง |
| GET | `/api/diagrams/:id/events?client=<id>` | สตรีม Server-Sent Events: `hello`, `presence` (ใครเปิดอยู่และเลือกอะไร), `saved`, `deleted` |
| POST | `/api/diagrams/:id/presence` | บอกชิ้นที่เลือกอยู่ `{ client, sel }` |

API ต้องเข้าสู่ระบบก่อน (cookie `np_sid`) และคำขอที่แก้ไขข้อมูลต้องส่ง header `X-NetPlan: 1` ผู้ดูแลระบบมี `/api/users` และ `/api/settings` เพิ่ม

การบันทึกที่ส่ง header `X-NetPlan-Rev: <rev ที่อ่านมา>` จะผ่านก็ต่อเมื่อผังบนเซิร์ฟเวอร์ยังเป็นรุ่นนั้น ถ้ามีคนบันทึกไปก่อน จะได้ `409` พร้อม `rev` และ `diagram` รุ่นล่าสุดกลับมาให้รวมแล้วส่งใหม่ ถ้าผังถูกลบไปแล้วได้ `410` ระบบอื่นที่ไม่ส่ง header นี้จะเขียนทับเหมือนเดิม

## ความปลอดภัย

สิ่งที่โปรแกรมทำให้แล้ว: รหัสผ่านเก็บแบบ scrypt, cookie แบบ HttpOnly + SameSite, ตรวจสิทธิ์ทุกคำขอที่ฝั่งเซิร์ฟเวอร์, กันการเดารหัสผ่าน (ผิด 10 ครั้งพัก 15 นาที), จำกัดการส่งอีเมลไม่เกิน 10 ครั้งต่อชั่วโมงต่อ IP, ส่ง header ความปลอดภัย (Strict-Transport-Security/HSTS แบบ includeSubDomains, Content-Security-Policy ที่อนุญาตเฉพาะสคริปต์ของหน้าโปรแกรมเองตาม SHA-256 hash โดยไม่เปิด `unsafe-inline` ให้สคริปต์, X-Frame-Options, Referrer-Policy), การยืนยันตัวตน 2 ขั้น (MFA) และไม่ให้คนสมัครใหม่เห็นผังจนกว่าผู้ดูแลระบบอนุมัติ

สิ่งที่ผู้ติดตั้งต้องทำเมื่อเปิดให้ใช้ผ่านอินเทอร์เน็ต:

1. **ใช้ HTTPS** วาง reverse proxy (เช่น Nginx, Caddy หรือ Cloudflare) ที่มีใบรับรอง SSL ไว้ข้างหน้า และให้ proxy ส่ง header `X-Forwarded-Proto: https` แล้วเปลี่ยน “ที่อยู่เว็บที่ใส่ในลิงก์อีเมล” เป็น `https://...`
   - ตั้งให้ proxy รับเฉพาะ TLS 1.2 ขึ้นไป (ปิด TLS 1.0/1.1) ถ้าใช้ Cloudflare: SSL/TLS → Edge Certificates → Minimum TLS Version = TLS 1.2 และเปิด Always Use HTTPS
   - ถ้าต้องการตัด cipher แบบ CBC ของ TLS 1.2 ออก (ให้เหลือเฉพาะ AEAD) ตั้งที่ Cloudflare: SSL/TLS → Edge Certificates → Cipher suites เลือกแบบ Modern
2. **ปิดพอร์ตตรง** ให้เข้าได้ผ่าน proxy เท่านั้น เช่น ผูกพอร์ตไว้ที่ `127.0.0.1:9000:8080` ใน docker-compose หรือปิดด้วย firewall
3. **สำรองข้อมูล** โฟลเดอร์ `data/` เป็นประจำด้วย `scripts/backup-data.sh` (มีทั้งผังและบัญชีผู้ใช้) และเก็บสำเนาไว้นอกเครื่องด้วย
4. ตั้งรหัสผ่าน admin ให้ยาว และอัปเดตระบบปฏิบัติการ/Docker สม่ำเสมอ
